README案：ペットケア共有アプリ（仮）
1. サービス概要（※最後に書いてOK）
* このサービスはどんなサービスか 家族やパートナー間で、ペットの食事、散歩、通院などの「お世話の記録」をリアルタイムで共有・管理できるサービスです。
* 誰の、どんな課題を、どう解決するか 「誰がいつ餌をあげたかわからない」「散歩に行ったか聞き忘れた」という飼い主家族のコミュニケーション不足を、シンプルな記録と通知機能で解決します。

2. このアイデアはどこから生まれたか
2-1. きっかけとなった体験・感情
* いつ： 家族で犬を飼い始めた頃や、忙しい平日。
* 状況： 「もう餌あげた？」「さっきあげたよ」という会話が毎日発生し、時には二重に餌をあげてしまったり、逆に誰もあげていなかったりした。
* 気持ち： ペットの健康に関わることなのに、情報が属人化していることに不安とストレスを感じた。
2-2. なぜそれが「気になった」のか
自分自身がプログラミングを学ぶ中で「情報のデータ化と共有」の効率性を重視するようになったことや、大切な家族であるペットに常に最高のケアを届けたいという責任感があるため。

3. 課題の整理
3-1. 表に見えている困りごと
お世話の重複や漏れが発生し、家族間での確認作業（LINEや口頭）が手間に感じる。
3-2. 本当に解決したい課題は何か
* なぜ？：お世話の状況が可視化されていないから。
* なぜ？：個々の家族が「誰かがやっただろう」と思い込んでしまうから。
* なぜ？：ペットに関するコミュニケーションが「確認」ばかりになり、余裕がなくなるから。 → 本当に解決したい課題： 家族全員がペットの状態を正しく把握し、責任を分担することで、ペットとの時間をより純粋に楽しめる心の余裕を作ること。

4. 想定ユーザーについて
4-1. 想定しているユーザー
* 年齢設定： 20代〜50代。
    * 理由：スマホ操作に慣れており、家族グループで家事や育児を分担する世代であるため。
* 生活・状況設定： 共働き世帯や、多忙な学生がいる家庭。
    * 理由：生活リズムがバラバラなため、対面での情報共有が難しい場面が多い。
* 環境設定： 室内でペット（犬・猫など）を飼育している。
    * 理由：食事やトイレの回数管理が、健康管理に直結しやすい環境。
4-2. 自分とユーザーの距離
* 自分自身 / 身近な誰か
* 理由：実際に自分もペットを飼っており、周囲の飼い主仲間からも同様の悩みを聞くことが多いため。
4-3. 実際に使われる可能性について
* 最初の人： 自分の家族、または友人。
* 場面： 帰宅時や、仕事の合間に「今、家でペットがどう過ごしているか」気になった時。
* 代わり： LINEのトークや、壁掛けのカレンダー、付箋。
* 置き換える理由： ログが流れない、過去の健康状態（通院歴など）を検索・振り返りやすい。
4-4. ユーザーがサービスを導入して利用するまでのイメージ
* きっかけ： 「また二重に餌をあげちゃった」という失敗。
* 最初の一歩： 代表者がグループを作成し、家族を招待する。招待を受けた家族は、それぞれ個別のユーザーアカウントを作成してグループに参加。 その後、共有するペットのプロフィールを登録。
* 継続理由： 「誰が」お世話をしたかが名前とともにリアルタイムで記録されるため、家族間での「ありがとう」のコミュニケーションが生まれ、お世話のモチベーション維持に繋がる。

5. 既存サービス・競合調査
5-1. 似たサービスの調査
* サービス名： ペットノートや犬の気持ち猫の気持ち などのアプリ
* できること： 飼育情報の閲覧、日記機能、健康管理。
5-2. それでも自分が作りたい理由
既存アプリは「情報収集（読み物）」や「個人の日記」の色が強く、家族間での「タスク完了共有」に特化したシンプルで使い勝手の良いものが意外と少ないと感じたため。
5-3. 差別化を一文で決める
多忙な家族が、1タップで「お世話完了」を伝え合い、ペットの幸せを分かち合えるアプリ。

6. このサービスで提供したい価値
6-1. ユーザーの変化
* 行動： 無駄な「確認LINE」が減り、スムーズにお世話が回るようになる。
* 気持ち： 「自分だけがやっている」という不満や、やり忘れへの罪悪感が減る。
* 考え方： お世話を「作業」ではなく、家族共通のプロジェクトとして捉えられるようになる。
6-2. 価値を一文で表す
このサービスは、家族でペットを飼育している人が、迷いなくお世話を分担し、健康管理を徹底できるようになるサービス。

7. このアプリで実現すること
MVPで作る機能
* ユーザー登録・ログイン（Sorcery）
* 家族（グループ）作成・招待機能
* 個別のユーザーアカウント同士をグループで紐付けをして、同一のペットデータを共有する機能
* ペットのプロフィール登録
* お世話項目のカスタマイズ（食事、散歩、トイレ等）
* 完了チェック機能（誰がいつやったかの記録）
* ログインをしたユーザーに基づいた、お世話をした人の名前とお世話をした日時の自動記録機能
本リリースで作る機能
* LINE通知機能（Messaging API）
* カレンダー表示（振り返り用）
* 体重・通院ログのグラフ化
* お世話のリマインド設定（Whenever等を使用）

8. このアプリの懸念点とその対策
懸念点
* 問題： 「記録すること自体」が面倒になり、使われなくなる。
* 対策： 極力入力項目を減らし、ボタン1つで完了報告ができるUIにする。また、通知が来ることのメリット（感謝のスタンプ機能など）を検討する。

10. 技術スタック
10-1. 使用予定の技術
* フレームワーク： Ruby on Rails
* DB： PostgreSQL
* デプロイ先： Render / Heroku
* ライブラリ： Sorcery, CarrierWave (画像投稿用), Line-bot-api
10-2. 技術選定の理由
* Rails： 現在学習中で、ActiveRecordを用いた複雑な関連付け（ユーザー×グループ×ペット）を実装するのに適しているため。
* LINE連携： ユーザーが日常的に使うツールに通知を飛ばすことで、アプリの定着率を高めるチャレンジをしたい。
